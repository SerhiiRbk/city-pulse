# Requirements Document

## Introduction

Crew Invite Link — дополнительный механизм приглашения в Crew через генерируемую ссылку. Позволяет Crew_Host и Crew_Moderator создать уникальную ссылку-приглашение, которую можно отправить через Telegram, WhatsApp или любой другой мессенджер. Зарегистрированный пользователь, перейдя по ссылке, видит диалог подтверждения с информацией о компании, мероприятии и пригласившем. Это расширяет возможности приглашения за пределы внутреннего поиска пользователей на платформе.

## Glossary

- **Crew**: Группа от 2 до 10 пользователей, созданная для совместного посещения конкретного события (определено в event-crew spec).
- **Crew_Host**: Пользователь, создавший Crew. Имеет полные права управления.
- **Crew_Moderator**: Участник Crew с правами приглашения и управления запросами на вступление.
- **Invite_Link**: Уникальная URL-ссылка, содержащая токен приглашения, которую можно передать через внешние каналы (мессенджеры, email, соцсети).
- **Invite_Token**: Криптографически случайный строковый идентификатор, встроенный в Invite_Link, используемый для идентификации приглашения.
- **Invite_Link_Service**: Бэкенд-сервис, отвечающий за генерацию, валидацию и обработку Invite_Link.
- **Join_Confirmation_Dialog**: Модальное окно, отображаемое пользователю при переходе по Invite_Link, содержащее информацию о Crew, событии и пригласившем.
- **Crew_Service**: Бэкенд-сервис, отвечающий за жизненный цикл Crew (определено в event-crew spec).
- **Notification_Service**: Существующая система уведомлений платформы.

## Requirements

### Requirement 1: Invite Link Generation

**User Story:** As a Crew_Host or Crew_Moderator, I want to generate a shareable invite link for my Crew so that I can invite friends via external messengers without searching for them on the platform.

#### Acceptance Criteria

1. WHEN a Crew_Host or Crew_Moderator requests an invite link, THE Invite_Link_Service SHALL generate a unique Invite_Link containing a cryptographically random Invite_Token of at least 32 characters.
2. WHEN an Invite_Link is generated, THE Invite_Link_Service SHALL associate the link with the Crew ID and the ID of the user who generated it (the inviter).
3. WHEN an Invite_Link is generated, THE Invite_Link_Service SHALL set an expiration time of 7 days from the moment of generation.
4. THE Invite_Link_Service SHALL format the link as `{base_url}/invite/crew/{invite_token}`.
5. IF a Crew_Host or Crew_Moderator requests an invite link when the Crew has reached its configured capacity, THEN THE Invite_Link_Service SHALL reject the request and display an error message indicating the Crew is full.
11. WHEN a Crew reaches full capacity (the last available spot is filled), THE Invite_Link_Service SHALL automatically deactivate all active Invite_Links for that Crew.
6. WHILE the Crew is in archived state, IF a Crew_Host or Crew_Moderator requests an invite link, THEN THE Invite_Link_Service SHALL reject the request and display an error message indicating the Crew is archived.
7. IF a Crew_Host or Crew_Moderator requests an invite link when the Crew already has 5 active (non-expired, non-revoked) invite links, THEN THE Invite_Link_Service SHALL reject the request and display an error message indicating the maximum number of active links has been reached.
8. THE Invite_Link_Service SHALL allow the Crew_Host or Crew_Moderator who generated an Invite_Link to revoke it, immediately marking the link as inactive.
9. IF a user navigates to an Invite_Link that is expired or revoked, THEN THE Invite_Link_Service SHALL display an error message indicating the link is no longer valid.
10. WHEN an Invite_Link's associated event is cancelled or the Crew is deleted, THE Invite_Link_Service SHALL immediately invalidate all active Invite_Links for that Crew.
12. WHEN the associated event has ended (event end time has passed), THE Invite_Link_Service SHALL prevent generation of new invite links and deactivate all existing active Invite_Links for that Crew.
13. THE Invite_Link_Service SHALL allow a single Invite_Link to be used by multiple users (the link is multi-use until it expires, is revoked, or the Crew fills up).
14. WHEN the user who generated an Invite_Link is removed from the Crew or leaves the Crew, THE Invite_Link_Service SHALL immediately deactivate all Invite_Links generated by that user.

### Requirement 2: Invite Link Sharing

**User Story:** As a Crew_Host or Crew_Moderator, I want to easily copy or share the invite link so that I can send it through any messenger or communication channel.

#### Acceptance Criteria

1. WHEN an Invite_Link is generated, THE Invite_Link_Service SHALL display the full Invite_Link URL as visible text along with a "Copy to clipboard" button.
2. WHEN the user clicks the "Copy to clipboard" button, THE Invite_Link_Service SHALL copy the full Invite_Link URL to the system clipboard and display a confirmation toast for 3 seconds.
3. IF the clipboard write operation fails, THEN THE Invite_Link_Service SHALL display an error message indicating the link could not be copied and keep the Invite_Link URL visible for manual selection.
4. WHERE the device supports the Web Share API, THE Invite_Link_Service SHALL display a "Share" button next to the "Copy to clipboard" button that triggers the native share dialog.
5. WHEN the native share dialog is triggered, THE Invite_Link_Service SHALL provide a pre-filled share text in the user's current interface language containing the Crew name and event name, along with the Invite_Link URL.
6. IF the user cancels or dismisses the native share dialog, THEN THE Invite_Link_Service SHALL return the user to the invite link view without displaying an error.

### Requirement 3: Invite Link Landing Page

**User Story:** As a user who received an invite link, I want to see clear information about the Crew and event when I open the link so that I can make an informed decision about joining.

#### Acceptance Criteria

1. WHEN a registered and authenticated user opens a valid Invite_Link, THE Invite_Link_Service SHALL display the Join_Confirmation_Dialog with the text: "Вы хотите присоединиться к компании «{crewName}» для посещения мероприятия «{eventName}» по приглашению от {inviterDisplayName}?"
2. WHEN a registered but unauthenticated user opens a valid Invite_Link, THE Invite_Link_Service SHALL redirect the user to the login page and preserve the Invite_Link destination for post-login redirect.
3. WHEN an unregistered user opens a valid Invite_Link, THE Invite_Link_Service SHALL redirect the user to the registration page and preserve the Invite_Link destination for post-registration redirect.
4. WHEN a user opens an Invite_Link with an expired Invite_Token, THE Invite_Link_Service SHALL display a message: "Эта ссылка-приглашение истекла. Попросите отправителя создать новую ссылку."
5. WHEN a user opens an Invite_Link with a revoked Invite_Token, THE Invite_Link_Service SHALL display a message: "Эта ссылка-приглашение больше не действительна."
6. WHEN a user opens an Invite_Link for a Crew that has been deleted, THE Invite_Link_Service SHALL display a message: "Компания больше не существует."
7. WHEN a user opens an Invite_Link for a Crew that is at full capacity, THE Invite_Link_Service SHALL redirect the user to the associated event detail page and display a toast message: "Компания уже заполнена. Свободных мест нет."
8. THE Join_Confirmation_Dialog SHALL display the event start date and time, event venue name, Crew name, number of current participants out of configured capacity (e.g., "4/6"), and number of available spots.
9. WHEN a user opens an Invite_Link for a Crew that is in archived state, THE Invite_Link_Service SHALL display a message: "Эта компания уже архивирована. Присоединение невозможно."
10. WHEN a user opens an Invite_Link with an Invite_Token that does not exist in the system, THE Invite_Link_Service SHALL display a message: "Ссылка-приглашение недействительна."
11. WHEN a user completes login or registration after being redirected from an Invite_Link, THE Invite_Link_Service SHALL redirect the user back to the Invite_Link landing page and display the Join_Confirmation_Dialog.
12. WHEN a user opens an Invite_Link for a Crew whose associated event has already ended, THE Invite_Link_Service SHALL display a message: "Мероприятие уже завершилось. Присоединение к компании невозможно."
13. WHEN a user who is already a participant of the target Crew opens the Invite_Link, THE Invite_Link_Service SHALL redirect the user directly to the Crew detail page without showing the Join_Confirmation_Dialog.
14. WHEN the user who generated the Invite_Link opens their own link, THE Invite_Link_Service SHALL redirect them directly to the Crew detail page without showing the Join_Confirmation_Dialog.
15. WHEN a platform-blocked user (is_blocked = true) opens an Invite_Link, THE Invite_Link_Service SHALL display a generic error message: "Ссылка-приглашение недействительна."
16. THE Join_Confirmation_Dialog SHALL display a "Отклонить" (Decline) button alongside the "Присоединиться" (Join) button.
17. WHEN a user clicks the "Отклонить" button in the Join_Confirmation_Dialog, THE Invite_Link_Service SHALL redirect the user to the associated event detail page without joining the Crew.
18. THE Invite_Link landing page SHALL include Open Graph meta tags (og:title, og:description, og:image) so that messengers display a rich preview when the link is shared, containing the Crew name, event name, and event cover image.
19. ALL user-facing error and status messages on the Invite_Link landing page SHALL be displayed in the user's current interface language.

### Requirement 4: Joining via Invite Link

**User Story:** As a user who received an invite link, I want to join the Crew by confirming the dialog so that I can attend the event with the group.

#### Acceptance Criteria

1. WHEN a user confirms joining via the Join_Confirmation_Dialog, THE Invite_Link_Service SHALL add the user as a Crew_Member with the same logic as accepting a standard Crew_Invitation, including granting access to the Crew_Chat.
2. WHEN a user successfully joins via Invite_Link, THE Invite_Link_Service SHALL automatically decline all pending Crew_Invitations for that user to other Crews for the same event.
3. WHEN a user successfully joins via Invite_Link, THE Invite_Link_Service SHALL automatically cancel all pending Join_Requests from that user to other Crews for the same event.
4. WHEN a user successfully joins via Invite_Link, THE Notification_Service SHALL notify all existing Crew participants that a new member joined.
5. WHEN a user successfully joins via Invite_Link, THE Invite_Link_Service SHALL redirect the user to the Crew detail page.
6. IF the user is already a participant of another Crew for the same event, THEN THE Invite_Link_Service SHALL display a message: "Вы уже состоите в другой компании для этого мероприятия. Покиньте текущую компанию, чтобы присоединиться к этой."
7. IF the user is already a participant of the target Crew, THEN THE Invite_Link_Service SHALL redirect the user to the Crew detail page without creating a duplicate membership.
8. IF the user is the Event_Organizer of the associated event (and the event is not a System_Event), THEN THE Invite_Link_Service SHALL display a message: "Организаторы мероприятия не могут присоединяться к компаниям."
9. IF the Crew reaches full capacity between the time the Join_Confirmation_Dialog is displayed and the time the user confirms, THEN THE Invite_Link_Service SHALL reject the join attempt, redirect the user to the associated event detail page, and display a toast message: "Компания уже заполнена. Свободных мест нет."
10. WHEN a user confirms joining, THE Invite_Link_Service SHALL re-validate the Invite_Token status (not expired, not revoked) before processing the join.
11. WHEN a Crew reaches full capacity, THE Invite_Link_Service SHALL automatically deactivate all active Invite_Links for that Crew so that subsequent users opening those links are immediately redirected to the event page with the "full" message.
12. IF a user who was previously removed from the Crew by the Crew_Host (kicked) opens an Invite_Link for that Crew, THEN THE Invite_Link_Service SHALL display a message: "Вы не можете присоединиться к этой компании."
13. IF a user who voluntarily left the Crew opens an Invite_Link for that Crew, THE Invite_Link_Service SHALL allow them to rejoin (show the standard Join_Confirmation_Dialog).
14. WHEN deactivated Invite_Links exist due to the Crew reaching full capacity, and a participant subsequently leaves the Crew freeing a spot, THE Invite_Link_Service SHALL NOT automatically reactivate the deactivated links. The Crew_Host or Crew_Moderator must generate new links manually.

### Requirement 5: Invite Link Management

**User Story:** As a Crew_Host or Crew_Moderator, I want to view and manage active invite links so that I can control access to my Crew.

#### Acceptance Criteria

1. WHEN a Crew_Host or Crew_Moderator opens the Crew management panel, THE Invite_Link_Service SHALL display a list of all active invite links with their creation date, expiration date, and the name of the user who generated each link, sorted by creation date descending.
2. WHEN a Crew_Host or Crew_Moderator revokes an invite link, THE Invite_Link_Service SHALL invalidate the link within 5 seconds so that subsequent uses display a message indicating the link is no longer valid.
3. THE Invite_Link_Service SHALL allow only the Crew_Host to revoke invite links generated by Crew_Moderators.
4. THE Invite_Link_Service SHALL allow Crew_Moderators to revoke only invite links they generated themselves.
5. WHEN an Invite_Link expires (7 days after generation), THE Invite_Link_Service SHALL automatically mark the link as expired and stop accepting new joins via that link.
6. WHEN a Crew is deleted, THE Invite_Link_Service SHALL invalidate all associated invite links.
7. WHEN a Crew transitions to archived state, THE Invite_Link_Service SHALL invalidate all associated invite links.
8. IF a Crew_Member or non-participant attempts to revoke an invite link, THEN THE Invite_Link_Service SHALL reject the action and display an error message indicating insufficient permissions.
9. WHEN a user attempts to join via an invite link and the Crew has reached its configured capacity, THE Invite_Link_Service SHALL reject the join attempt and display a message indicating the Crew is full.
10. THE Invite_Link_Service SHALL enforce a maximum of 5 active (non-expired, non-revoked) invite links per Crew at any time.

### Requirement 6: Invite Link Security and Limits

**User Story:** As a platform operator, I want to enforce security measures on invite links so that they cannot be abused.

#### Acceptance Criteria

1. THE Invite_Link_Service SHALL generate Invite_Tokens using a cryptographically secure random generator producing URL-safe strings of 32 to 128 characters.
2. THE Invite_Link_Service SHALL enforce a maximum of 5 active invite links per Crew at any time.
3. THE Invite_Link_Service SHALL count each successful join via an Invite_Link toward the Crew's overall invitation limit of 20 (shared with standard invitations).
4. IF the Crew's total invitation count (standard invitations plus invite-link joins) reaches 20, THEN THE Invite_Link_Service SHALL prevent generation of new invite links and deactivate all existing active invite links for that Crew.
5. THE Invite_Link_Service SHALL rate-limit invite link generation to a maximum of 10 links per Crew per rolling 24-hour window.
6. IF a user who has blocked the Crew_Host opens an Invite_Link for that Crew, THEN THE Invite_Link_Service SHALL reject the join attempt and display an error message indicating the user cannot join this Crew.
7. IF a user who has disabled invitation notifications opens an Invite_Link, THEN THE Invite_Link_Service SHALL still allow joining (the link is an explicit user action, not a push notification).
8. THE Invite_Link_Service SHALL log each invite link generation and each join attempt, recording at minimum the acting user identifier, Crew identifier, timestamp, and action outcome (success or failure reason).
9. THE Invite_Link_Service SHALL expire each invite link 7 days after generation, after which the link SHALL return an error message indicating the link has expired.
10. IF a user opens an Invite_Link for a Crew that has reached its configured capacity, THEN THE Invite_Link_Service SHALL redirect the user to the associated event detail page and display a toast message indicating the Crew is full.
11. IF a user who is already a participant of another Crew for the same event opens an Invite_Link, THEN THE Invite_Link_Service SHALL reject the join attempt and display an error message indicating the user is already in a Crew for this event.
12. IF a platform-blocked user (is_blocked = true) attempts to join via an Invite_Link, THEN THE Invite_Link_Service SHALL reject the join attempt and display a generic error message.

### Requirement 7: Invite Link Notifications

**User Story:** As a Crew participant, I want to be notified when someone joins via an invite link so that I know who is in my Crew.

#### Acceptance Criteria

1. WHEN a user joins a Crew via Invite_Link, THE Notification_Service SHALL deliver a notification to all existing Crew participants (excluding the joining user) within 5 seconds, with the text "{userName} присоединился к компании по ссылке от {inviterName}" displayed in each recipient's interface language.
2. WHEN a user joins a Crew via Invite_Link, THE Invite_Link_Service SHALL insert a system message in the Crew_Chat in each participant's interface language indicating that {userName} joined the crew via invite link from {inviterName}.
3. IF the Notification_Service fails to deliver a join notification to one or more participants, THEN THE Notification_Service SHALL retry delivery up to 3 times with exponential backoff and SHALL NOT block the join operation or affect the system message insertion in Crew_Chat.
